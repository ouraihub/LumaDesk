- 翻译结果是新 turn，不覆盖源 turn。

### 2.2 当前基线与目标实现

当前代码缺少的能力按新项目目标继续实现；下表描述缺口和下一条真实链路，不是永久产品限制：

| AutoNote 行为 | 当前基线 | 下一实现合同 |
|---|---|---|
| 保存到笔记 | 无宿主回调 | Phase 2 增加可选宿主动作；无回调时隐藏 |
| 插入编辑器 | 无编辑器回调 | Phase 2 增加可选宿主动作；失败可重试 |

| 删除单个回复 | 只有删除 conversation | Phase 3 按 `conversation_id + turn_id + attempt_id` 删除 |
| 分支 | 无 branch API | Phase 3 增加 parent/selected 关系和新 ID |

| 图片附件 UI | 只有 LumaKit 图片校验/编码 | Phase 4 增加宿主文件选择、失败恢复和 ImageRef |

## Phase 2：宿主动作与更多菜单

### 3.1 只移植 AutoNote 已运行的无历史变更动作

首先实现 AutoNote 已有、且不需要改 `chat.db` schema 的三个动作：

```text
保存到笔记
插入编辑器
导出 Markdown
```

### 3.2 LumaKit 动作合同

`lumakit-ui/src/chat.rs`：

```rust

ChatAction::InsertMarkdown { attempt_id: String, markdown: String }
ChatAction::ExportMarkdown { attempt_id: String, markdown: String }
```

证据映射：

```text

AutoNote onInsert(turn.text)         → InsertMarkdown
AutoNote onExportMarkdown(turn.text) → ExportMarkdown
```

不新增 `OpenMore` 动作；更多菜单是 UI 状态，不是宿主业务动作。

规则：

- 传原始 Markdown；
- 空文本、Running 状态不发动作；
- `attempt_id` 防止异步回调误写其他回复；
- ChatPanel 不访问 SQLite、笔记或文件系统。

### 3.3 LumaDesk 宿主合同

`LumaDesk/src/chat.rs` 增加最小可选回调：

没有回调时隐藏对应动作；不显示占位按钮。

### 3.4 失败语义

- 回调失败：保留回复、显示错误、允许再次执行；
- 不写 `chat.db`；
- 导出由宿主使用临时文件+替换；
- 菜单 Escape/遮罩只关闭，不执行；
- 不使用通用事件总线。

## Phase 3：按 AutoNote 历史端口实现回复候选操作

### 4.1 直接对齐 AutoNote 历史端口

AutoNote 已运行端口：

```ts
editTurn(conversationId, turnId, text, expectedText)
removeTurn(conversationId, turnId)
fork(conversationId, turnId)
selectTurn(conversationId, turnId)
```

这里的 AutoNote `turnId` 是 UI 候选回复的 ID，不等于当前 LumaDesk 的 `Turn.id`（问题 ID）或 `Attempt.id`（候选 ID）。LumaDesk 移植必须显式携带两级定位：`turn_id + attempt_id`，再由共享核心验证所属 conversation。

LumaDesk API：

```rust
pub fn edit_attempt(&mut self, turn_id: &str, attempt_id: &str,
    expected_text: &str, next_text: &str) -> Result<(), String>;
pub fn delete_attempt(&mut self, turn_id: &str, attempt_id: &str) -> Result<(), String>;
pub fn fork_attempt(&mut self, turn_id: &str, attempt_id: &str) -> Result<String, String>;
pub fn select_attempt(&mut self, turn_id: &str, attempt_id: &str) -> Result<(), String>;
pub fn copy_conversation(&mut self, conversation_id: &str) -> Result<String, String>;

// UI 只返回意图；宿主调用上面的 ChatSession 方法。
ChatAction::EditAttempt { turn_id: String, attempt_id: String }
ChatAction::SubmitEdit { turn_id: String, attempt_id: String,
    expected_text: String, next_text: String }
ChatAction::DeleteAttempt { turn_id: String, attempt_id: String }
ChatAction::ForkAttempt { turn_id: String, attempt_id: String }
ChatAction::CopyConversation { conversation_id: String }
ChatAction::SelectAttempt { turn_id: String, attempt_id: String }

// 以上API不是当前已有实现；它们是Phase 3的实现目标。
```

### 4.2 AutoNote 规则 → LumaDesk 规则

| AutoNote 代码证据 | 移植实现 |
|---|---|
| `hasChildren(turn)` 检查 `parentId/supersedesId` | Phase 3 前必须先明确 LumaDesk 线性 attempts 如何表达“已有子候选”；没有字段前只能禁止编辑/删除有多个候选的 turn，不能宣称等价 |
| `canEdit`: `status !== running && !hasChildren` | 仅 Completed 且无后续候选可编辑；运行中、失败、已有后续候选拒绝 |
| `canDelete`: `canEdit && selectedTurnId !== turn.id` | 先定义 LumaDesk selected attempt；若当前选中候选仍是后续上下文源，删除必须拒绝或先显式切换，不能默认删除 |
| `history.editTurn(...expectedText)` | SQL `UPDATE attempts SET text=? WHERE id=? AND turn_id=? AND text=?`; 受影响行必须为1，否则冲突 |
| `history.removeTurn` | 单事务删除目标 attempt，保留其它候选和问题；空问题是否删除按实现测试定案 |
| `history.fork` | AutoNote 复制目标候选以前的线性内容；LumaDesk 复制 conversation/turn/attempt，并重新生成全部 ID |
| `history.selectTurn` | LumaDesk 当前 `chat.db` 只有 conversation selected，没有 selected attempt；Phase 3 必须增加明确字段/表项并持久化，不能只改变 UI 高亮 |

AutoNote 的 `ChatSession.show()` 会用 `selectedTurnId` 恢复选择，且 `mutateReply()` 在 select/branch/remove/fork 成功后重新读取 conversation。LumaDesk 也必须在事务提交后重新读回或等价更新 saved/history，不能只修改当前内存引用。

### 4.3 动作

```rust
ChatAction::EditAttempt { turn_id: String, attempt_id: String }
ChatAction::SubmitEdit {
    turn_id: String,
    attempt_id: String,
    expected_text: String,
    next_text: String,
}
ChatAction::DeleteAttempt { turn_id: String, attempt_id: String }
ChatAction::ForkAttempt { turn_id: String, attempt_id: String }
ChatAction::CopyConversation { conversation_id: String }
ChatAction::SelectAttempt { turn_id: String, attempt_id: String }
```

### 4.4 事务和失败

所有历史操作必须：

- 检查 `busy`/`save_error`；
- 单个 SQLite transaction；
- 内存状态只在 commit 成功后更新；
- 失败保持原 UI 和 selection；
- 使用复合定位 `conversation_id + turn_id + attempt_id`，不用数组下标；
- 迟到的异步结果发现 attempt 已删除时丢弃。

### 4.5 历史规则

#### 删除

- 只删目标 attempt；
- 其它候选和其它 conversation 不变；
- turn 无候选时删除 turn；
- conversation 无 turn 时保留空 conversation 和草稿；
- selected attempt 被删除时选择同 turn 末尾候选或前一个 Completed 候选；
- 删除确认只能由明确按钮触发。

#### 编辑

- 显示原始 Markdown；
- 空文本/超过现有 1MiB 历史边界拒绝；
- CAS 冲突返回“内容已被其他操作修改”；
- 不自动重新请求；
- 保留源模型和 usage 快照，但增加“正文已编辑”状态的必要性应在实现时定案。

#### 分支

AutoNote 的 `fork(conversationId, turnId)` 是已运行合同。LumaDesk 初期按同语义：

- 复制目标 attempt 之前的线性历史；
- 新 conversation 选中；
- 不复制 Running job；
- 所有 ID 重生成；
- 原 conversation 不变；
- 模型、正文、usage、价格快照保留。

#### 复制对话

- 复制完整 conversation；
- 标题加“副本”；
- 全部 ID 重生成；
- 原 conversation 不变；
- 新 conversation 选中。

### 5.2 搜索来源：事件和正文分离

AutoNote 的证据：`RunRequest.webSearch`；`RunEvent.search_start/search_result`；`run-session.svelte.ts:380-395` 写入 `turn.search`；`MessageItem.svelte:340-353` 单独渲染来源。

LumaDesk 合同：

```rust
pub enum ChatEvent {
    SearchStart { attempt_id: String, query: String, provider: String },
    SearchResult { attempt_id: String, query: String, provider: String, hits: Vec<SearchHit> },
    SearchFailed { attempt_id: String, error: String },
    SearchCancelled { attempt_id: String },
}

pub struct SearchState {
    pub status: SearchStatus, // Idle | Searching | Complete | Failed | Cancelled
    pub query: Option<String>,
    pub provider: Option<String>,
    pub hits: Vec<SearchHit>,
    pub error: Option<String>,
}
```

每个事件还必须携带所属 `conversation_id` 和 `turn_id`；归约器按三层 ID 校验目标 attempt，重复终态和迟到事件丢弃。无结果使用 `SearchResult { hits: vec![] }`，失败、取消不能伪装成空结果。

`Attempt` 增加 `#[serde(default)] pub search: SearchState`。运行时必须真实发出 SearchStart/SearchResult；不能只编码 native search tool 后丢弃结果。`SearchHit.url` 只允许 HTTP(S)，来源不能拼入 `Attempt.text`；`webSearch` 是本次请求开关，不修改模型默认配置。

验收：能观察事件；重启后正文/来源分离；成功、失败、取消、无结果可区分；没有完整事件链时不显示联网按钮。

### 5.3 图片附件：引用持久化，不存 Base64 历史

AutoNote 的证据：`ChatPanel.svelte:507-617` 按 `canVision` 门控，限制 MIME/数量/大小，预览与请求数据分离，发送失败恢复；`RunRequest.images` 发原始数据；`Turn.images` 只保存 `ImageRef`。

LumaDesk UI 动作：

```rust
ChatAction::AttachImages(Vec<ImagePart>)
ChatAction::RemoveImage(usize)
```

ChatPanel 持有未发送 `AttachedImage { part: ImagePart, preview: TextureHandle }`。发送前再次调用已有 `images::validate()`，检查 `supports_vision`；接受后清理预览，拒绝/保存失败恢复草稿和附件。

历史新增引用字段：

```rust
pub struct ImageRef {
    pub id: String,
    pub mime: String,
    pub bytes: u64,
    pub width: Option<u32>,
    pub height: Option<u32>,
    pub storage_key: String,
}
```

图片二进制存储位置、清理和备份必须和 `chat.db` 一起实现；不把 Base64 塞进普通历史字段，不把临时路径当永久引用，不把任意本地路径交给协议层。

验收：真实魔数/大小/数量/MIME 校验；不支持视觉时禁用；发送失败恢复；历史只保存引用；重启可读或明确“图片已过期”；重试按 AutoNote 复用源图片数据或明确失败。

### 5.4 生成图片：真实消费者先于按钮

AutoNote 的证据：`RunRequest.generateImage`；`run-session.svelte.ts:416-440` 从 tool result payload `images` 追加 `turn.generated`；`MessageItem.svelte:195-209` 渲染 `generated`。

LumaDesk 实施顺序固定为：

```text
真实图片请求消费者
→ 有界响应和图片校验
→ AiRun/ChatEvent GeneratedImages
→ Attempt.generated
→ chat.db
→ 回复图片区
```

最小请求/结果合同：

```rust
pub struct ImageGenerationRequest {
    pub prompt: String,
    pub reference_images: Vec<ImagePart>,
    pub size: Option<String>,
}
pub struct GeneratedImage {
    pub id: String,
    pub mime: String,
    pub bytes: u64,
    pub storage_key: String,
    pub width: Option<u32>,
    pub height: Option<u32>,
}
```

必须覆盖 `/images/generations` 或协议等价端点、非2xx、超大响应、无效 Base64、错误 MIME、取消、usage/价格快照。没有真实消费者前禁止生成图片按钮；失败不展示假缩略图。

### 5.5 统一状态机与交付顺序

```text
Idle
→ 校验模型/输入/图片/参数
→ 写入 Running attempt
→ 启动请求
→ 增量事件
→ 唯一 End
→ 写入终态
→ Idle
```

顺序：

```text
翻译：Attempt.kind + 新请求字段
→ 搜索：ChatEvent + SearchState
→ 图片附件：本地引用与恢复
→ 生成图片：真实消费者、回环测试、持久化、UI
```

所有阶段：保存失败阻止后续写操作；失败保留草稿/附件/正文；迟到事件带 attempt ID 且目标删除后丢弃；取消/失败不进入普通上下文；终态只能提交一次。

## 6. 逐阶段验收依据

### Phase 2

参考行为：AutoNote `onSaveNote`、`onInsert`、`onExportMarkdown`，无历史端口调用。

验收：无宿主回调不显示入口；回调收到原始 Markdown；失败不改变回复；导出失败不留下半文件；Escape 不执行动作。

### Phase 3

参考行为：AutoNote `editTurn`、`removeTurn`、`fork`、`selectTurn`。

验收：单条候选删除不影响其它候选；编辑使用 expected text 冲突保护；fork 重新生成 ID 且原会话不变；选择候选改变后续上下文来源；重启结果一致。

### Phase 4

参考行为：AutoNote `RunRequest`、`RunEvent`、`ChatTurn`、`MessageItem`。

验收：翻译是新请求和新候选；来源与正文分离；附件发送失败可恢复；图片请求和生成结果经过真实回环 HTTP；图片/来源/翻译重启可恢复；取消、超时、非2xx、损坏响应不产生假成功。

## 7. 文档与实现约束

- 参考项目已运行代码是行为依据，LumaDesk 只转换为 Rust/egui，不复制 Svelte/bits-ui。
- 每个 Phase 先实现参考合同对应后端，再接 UI。
- 没有真实消费者不添加入口。
- 不引入通用事件总线、ORM、Repository trait。
- 所有动作使用稳定业务 ID，禁止数组下标定位。
- 每阶段独立测试和实窗验收。
