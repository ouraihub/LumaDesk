# 网络搜索多密钥与模型服务交互统一

> 日期：2026-11-09<br>
> 范围：设置 → 网络搜索的密钥区与密钥管理；设置 → 模型服务的密钥区（改用共享组件）<br>
> 参考：LumaDesk 现有模型服务密钥交互（其结构来自 ThinkRail Native `providers/detail/key.rs`、`providers/keys.rs`）

## 1. 背景与结论

网络搜索后端早已支持每个服务商最多 16 个加密密钥，并在 HTTP 401/403/429 时按列表顺序轮换（`src/search_settings/network.rs`）。用户感知为“只能加一个”，原因是界面：

- 卡片主区是“新密钥”输入框 + 一行 `·` 拼接的全部掩码，多密钥入口是不显眼的 `List` 图标。
- 密钥弹窗是另一套样式（文字按钮“修改/显示/复制/删除”、行内删除确认），与模型服务的图标操作、独立确认不一致。
- 卡片“保存”同时提交地址、用户名和新密钥，地址非法时密钥也提交失败。
- 没有首选密钥，总是从第一个开始轮换。

用户确认的决定（2026-11-09）：

| # | 决定 |
| --- | --- |
| 1 | 统一放在 `lumakit-design::components::settings` 的共享无状态组件中，模型服务与网络搜索都改用它 |
| 2 | 网络搜索增加首选密钥（使用此密钥），运行时从首选密钥开始轮换 |
| 3 | 密钥独立加密、立即提交；卡片“保存”只提交基础地址和 SearXNG 用户名 |
| 4 | 只对齐 LumaDesk 现有模型服务，不新增密钥标签、单独启停、逐密钥检测 |
| 5 | “直接获取”不使用密钥，保持无密钥区 |

## 2. 共享组件合同（`lumakit_design::components::settings`）

新文件 `components/settings/keys.rs`，由 `settings` 重新导出。组件无状态：不持有密钥、草稿或存储，所有意图经回调交给宿主。

| 组件 | 内容 | 宿主提供 |
| --- | --- | --- |
| `KeyRow` | 32px 边框值框：掩码或已显示明文、可选 `+N`、图标按钮（显示/隐藏、复制、修改、删除…），可选“使用此密钥” | 显示文本、是否已显示、其余数量、各回调（缺省则不显示该按钮）、禁用 |
| `KeyManager` | 弹窗主体：上限说明、已保存密钥行、“添加密钥/修改密钥”字段、修改时“空草稿不会清空原密钥”、“取消修改”与“保存新密钥/保存修改后的密钥” | 说明文字、`KeyRow` 列表、输入控件、是否修改中、保存/取消修改回调、禁用 |
| `key_manage_button` | 描边 `KeyRound` 图标按钮，名称“密钥管理” | id 与点击 |
| `delete_confirm` | “确认删除”标题、说明、取消 / 危险色确认删除 | 说明、两个回调 |

无障碍：所有动作用 Kit `Button`（角色 Button/Link、可 Tab 聚焦、Enter/空格激活），图标按钮带可访问名称与提示；“使用此密钥”带选中状态。模型服务原密钥行用的 `IconButton` 不可键盘聚焦，本次随迁移改正。

## 3. 界面结构（两页一致）

```text
API 密钥 · 获取密钥    （SearXNG：密码（可选））
[ 首选密钥掩码  +N  👁 ] [🔑] [检测]          有密钥
[ 输入框     ] [加密保存] [🔑] [检测]  无密钥；Enter 同样保存
密钥使用方式  失败时轮换
      仅在 HTTP 401/403/429 时换下一个已保存密钥，不跨服务商重试
```

- 主行默认只显示眼睛；显示明文后出现复制、修改、删除。修改打开密钥弹窗并进入修改状态；删除进入确认。
- 密钥弹窗：标题“密钥管理 · 服务商”，`KeyManager`，页脚“完成”；Esc 关闭并恢复先前焦点。多于一个密钥时每行有“使用此密钥”。
- 删除确认独立显示（不再是弹窗内的行内确认）；取消回到之前的界面。
- 网络搜索卡片其余部分不变：标题、说明、官网、服务商选择、基础地址（带复制）、卡片“保存”与状态、取消检测。检测改为与模型服务相同的文字按钮“检测”。

## 4. 数据与运行时

### 4.1 存储

- `settings.db` 迁移 v2（只追加）：`ALTER TABLE search_configs ADD COLUMN selected_key TEXT`。旧库读回为空，等价于“首个密钥”。
- `SearchConfigRow` / `Config` 增加 `selected_key: Option<String>`；旧 `search-settings.json` 导入时缺省为空（`serde(default)`）。
- 校验：`selected_key` 必须指向本服务商已保存的密钥；否则拒绝保存/读取（“密钥配置无效”），不静默修正。

### 4.2 提交语义

| 操作 | 提交内容 | 失败 |
| --- | --- | --- |
| 卡片“保存” | 基础地址（空则恢复默认）、SearXNG 用户名 | 保留草稿；密钥不受影响 |
| 加密保存 / 保存新密钥 | 追加一个密钥；尚无首选时设为首选 | 原密钥列表与首选不变，输入草稿保留 |
| 保存修改后的密钥 | 替换该密钥密文，id 不变 | 原密文保留 |
| 使用此密钥 | 只改首选 | 恢复原首选 |
| 确认删除 | 删除该密钥；若为首选则改为剩余第一个 | 原列表保留 |
| 检测 | 先按卡片“保存”提交地址/用户名，再用已保存密钥请求 | 检测失败不回滚已保存配置 |

每次提交仍是整份搜索设置的单事务写入（`settings_store::save_search`），成功后才替换内存中的已保存状态。

### 4.3 轮换顺序

搜索与读取都按“首选密钥起，按列表顺序循环”尝试（与模型服务 `(first + offset) % n` 相同）；仍只在 401/403/429 换下一个，业务错误与其它状态码立即失败。
