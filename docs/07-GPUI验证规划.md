# GPUI Kit 功能等价验证规划

## 决策与基线

可行性见工作区 `docs/Navop UI框架用于LumaDesk的可行性分析.md`。本轮从干净 main 创建 LumaDesk、LumaKit 同名分支 `experiment/gpui-kit`。不提交用户未要求的 commit，不覆盖既有 dist/LumaDesk 正式产物。

锁定 crates.io `gpui-kit = "=0.9.0"` 默认组件/资源与默认 GPUI 后端（gpui-pre 0.3.11）。该发行版的 gpui-fast 为可选 feature，本项目不启用。无需 Navop fork、JS Shell、WebView、Dock 或插件系统。API 以实际锁定包源码为准。

## 交付范围

本轮是当前已实现功能的完整 UI 适配，不是 Hello World 或只实现聊天：

- 启动台、应用页签、侧栏、返回、设置搜索、启动失败和关闭保护。
- 聊天：模型选择、历史搜索/切换/删除、新对话、流式发送/停止/重试、候选/编辑/分支/复制、更多菜单、来源/工具/诊断/用量、Markdown、附件和生成图片、搜索/推理/图片工具控制、快捷工具显示持久化、展开输入和滚动跟随。
- 模型服务：服务商/线路管理、三协议、独立启用提交、密钥增删改显隐复制、模型检测与选择同步、搜索分组筛选、手动模型能力/价格/推理编辑。
- 网络搜索：Tavily/Brave/Exa，Direct/Jina 读取，配置/密钥、黑名单/结果数/截断、真实检测/结果和取消。
- MCP：当前服务器配置、URL 校验、启用/信任和删除；不声称已完成工具宿主。
- 外观：浅色/深色/系统/简洁浅色，强调色、背景、密度，保留数据库偏好。
- 数据与安全：数据库不迁 schema、单写实例锁、DPAPI、脱敏、请求取消、保存失败阻止继续、后台归约和关闭仲裁。

当前未接入的笔记/工作/知识库/翻译等业务维持明确未接入状态，不伪造完成。不存在的宿主操作不能变成可点击的空回调。

## 顺序

1. 完成本规划并建立基线清单。
2. 写概要设计，确定共享核心与 UI 的边界。
3. 写详细设计，固定实体接口、事件归约、迁移文件及验收。
4. 按独立边界实现模型设置、共享聊天、其它设置；集成窗口与发布。
5. 集成后统一构建、行为验证及实际窗口检查；发现错误修复后验证受影响路径。
6. 记录实际结果、已知限制与验证证据，不把编译通过写成视觉通过。

## 数据隔离与验收

验证程序默认使用独立 GPUI 数据目录；允许显式 LUMADESK_DATA_DIR，但本轮不访问正式用户资料。验证输出 dist/LumaDesk-GPUI，不替换 dist/LumaDesk。

使用回环 HTTP 服务驱动真实请求/流式/持久化链路，不需要生产密钥、不发生付费请求。它证明应用行为，不替代商业供应商兼容性测试。实窗覆盖正常/错误/生成中、窄窗 320/375/414/768 逻辑宽度、中文显示/输入与焦点、保存重启、最小化后台完成。无法自动观察的 IME 候选或屏幕阅读器项目明确记录，不宣称通过。

## 最小化原则

复用 ChatSession、ChatAction、ModelCatalog、CatalogStore、settings_store、请求函数与安全边界。只建立实际共享聊天组件 `lumakit-gpui`，不建设通用后端 factory。LumaDesk 切换后不依赖 eframe/lumakit-egui；LumaKit 的 egui adapter 暂留给现有独立 egui 示例，不破坏无关消费者。
