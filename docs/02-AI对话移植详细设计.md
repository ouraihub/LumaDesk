# AI 对话详细设计

日期：2026-10-24。状态：文本聊天、候选持久化、搜索/工具事件、输入附件、原生搜索/推理控制和图片生成消费者已实施；输入区与媒体回环、重启、正式打包已验收。翻译 UI、真实 MCP 宿主审批、图片粘贴预览及参考图编辑仍按对应任务实现。上位方案：[01](01-AI对话移植与LumaKit复用设计.md)。

本文面向新项目实现。现有代码是可运行基线，不是产品能力上限；允许迁移 `chat.db` schema、重做 ChatSession API 和扩展协议事件。任何已公开能力都必须完成真实请求、事件归约、持久化、重启恢复和失败验收。

## 1. 文件与模块

- `LumaKit/crates/lumakit-ai/src/chat.rs`：会话、候选关系、运行事件、翻译/搜索/工具/媒体状态、迁移和持久化；不依赖 egui。
- `LumaKit/crates/lumakit-ai/src/protocol.rs`：三协议请求/响应边界，统一输出文本、搜索、工具、推理、usage 和图片事件。
- `LumaKit/crates/lumakit-ai/src/images.rs`：图片 MIME、魔数、数量、Base64 和大小校验；媒体文件存储由 chat 数据层负责。
- `LumaKit/crates/lumakit-ui/src/chat.rs`：无密钥视图、能力状态和 ChatAction；按真实功能增长，不预置空动作。
- `LumaKit/crates/lumakit-egui/`：聊天面板、候选操作、翻译、来源、附件和生成图片显示；不访问数据库或密钥。
- `LumaDesk/src/chat.rs`：组合层、模型解析和宿主保存/插入/导出回调。
- 独立消费宿主：真实回环 HTTP、迁移、重启和媒体验收，不引用 LumaDesk 源文件。

## 2. 核心 API 合同

核心 API 以目标产品能力为准；下列现有方法是文本基线，新增方法必须沿同一 session 和事件链实现，不为旧签名保留错误边界。所有稳定 ID 与协议/模型引用均进入持久化合同。

实现顺序：先扩展持久化和事件归约，再接 UI；任何能力缺少真实消费者时不显示入口。
```rust
pub struct ChatSession { /* 仓库、状态、任务；无 egui */ }
impl ChatSession {
    pub fn open(path: &Path, wake: Arc<dyn Fn() + Send + Sync>) -> Result<Self, String>;
    pub fn history(&self) -> &History;
    pub fn selected(&self) -> Option<&Conversation>;
    pub fn busy(&self) -> bool;
    pub fn save_failed(&self) -> bool;
    pub fn notice(&self) -> &str;
    pub fn poll(&mut self);
    pub fn cancel(&mut self);
    pub fn can_close(&mut self) -> bool;
    pub fn new_conversation(&mut self);
    pub fn select_conversation(&mut self, id: &str);
    pub fn delete_conversation(&mut self, id: &str);
    pub fn select_model(&mut self, model: ModelRef);
    pub fn set_draft(&mut self, text: String);
    pub fn retry_save(&mut self);
    pub fn send(&mut self, connection: AiConnection);
    pub fn retry(&mut self, connection: AiConnection);
    pub fn request_model(&self, retry: bool) -> Result<ModelRef, String>;
    pub fn report(&mut self, message: String);
}
```

`History` 的目标模型包含 conversation、turn、attempt、selected attempt、候选父关系、翻译来源、搜索状态、输入/生成图片引用、usage/价格快照和 schema version。`Attempt.kind` 至少区分 `Reply` 与 `Translation`；普通上下文默认只使用选中的已完成 Reply。失败、取消和部分正文保留展示，但不默认回灌。

发送、重试、翻译、搜索、工具、推理和图片请求都必须把 `conversation_id + turn_id + attempt_id` 带入事件。事件归约只能提交一次终态；目标被删除或事件身份过期时丢弃。


### 3.1 工具配置、MCP、Skills 与审批入口

参考 pi 的边界，LumaDesk 采用“配置先于连接、信任先于暴露、暴露先于调用”的顺序：

- **配置层**：全局 MCP 配置保存服务器地址/stdio 命令、启用状态、工具暴露策略和超时；项目配置只能覆盖 `enabled`、`exposure`、`toolExposure`，且只有项目已信任时才读取。服务器名只允许稳定安全字符，并拒绝 `-`/`_` 命名冲突。
- **连接层**：服务器按需连接，连接状态为 `connecting/connected/disconnected/needs-auth/failed/closed`；只读调用可在瞬态连接错误后重试一次，写调用不自动重试，避免重复副作用。HTTP 仅 HTTPS 或 loopback，stdio 的命令、cwd、env 由宿主策略校验。
- **工具层**：先校验工具名、描述和 JSON Schema，再映射为稳定名称 `mcp__<server>__<tool>`；`direct` 直接给模型、`deferred` 由工具搜索后暴露、`codemode` 只供受控脚本、`hidden` 不可达。工具结果限制模型可见大小；完整输出落临时文件，不把超大正文塞进上下文。
- **审批层**：静态 `authorize` 先判断来源、工具暴露、只读/副作用和项目���信任；动态 `approve` 再交 UI。审批请求绑定 `conversation_id + turn_id + attempt_id + call_id`，展示工具名、参数摘要、来源服务器和风险；关闭、取消、超时均按拒绝处理。允许一次只作用于当前调用，不做隐式永久授权。
- **Skills 层**：只扫描受信来源的 `SKILL.md`；名称限定小写字母/数字/连字符，描述和正文有大小上限，frontmatter 只接受标量字段；安装先生成 digest preview，用户确认相同 digest 后才写入，运行时使用固定 `id + revision` 快照，修改后拒绝旧快照。Skills 只进入 system prompt/上下文，不直接获得工具权限。
- **结果层**：未知工具、拒绝、`isError`、MCP transport unknown、schema/权限错误分别记录到 `Attempt.tool_events`；工具结果不拼入回答正文，工具已执行后失败不得自动重试。密钥不进入历史、事件、日志或模型可见参数摘要。

最小宿主接缝沿用现有 `lumakit-ai::AiHost`，不再新增一层 trait：`tools()` 返回经过 exposure/信任过滤的 `ToolSpec`，`authorize()` 做静态门控，`approve()` 连接审批 UI，`call_tool()` 调用白名单本地工具或已信任 `McpClient`。`ChatSession` 负责事件身份、持久化和恢复；宿主负责配置、连接生命周期、审批 UI 和取消信号。

当前实现状态：`lumakit-ai` 已有 MCP URL/信任边界、Skills digest/revision 快照、AiHost 四个运行接缝和 ChatSession 工具事件持久化；LumaDesk 尚缺 MCP 配置 UI、Skills 受信目录绑定、真实 AiHost 组合和审批 UI。没有这些真实宿主能力前不显示工具入口。
## 3. UI 合同

`ModelOption { model: ModelRef, name: String, provider: String, endpoint: String }`。不携带密钥、完整连接或文件路径。
`ChatAction` 按已接通能力增长，目标包括：New、Select、Delete、SelectModel、Draft、Send、Retry、RetryWith、Stop、Translate、EditAttempt、DeleteAttempt、ForkAttempt、SelectAttempt、AttachImages、RemoveImage、Save、Insert、Export 和 OpenSettings。无真实后端/宿主能力时不显示入口。

`ChatPanel::show(&mut self, ui, session_view, options, host_capabilities) -> Vec<ChatAction>` 只绘制与收集动作；输入、候选选择、附件预览和菜单状态属于 UI，历史、事件、密钥和媒体持久化属于 session/host。

头部固定，composer 先占位，transcript 只用剩余区域。候选、来源、工具、思考、附件和生成图片都独立于正文显示；原始 Markdown 仍是复制/持久化来源。链接仅 HTTP(S)，不执行 HTML，不自动获取远程图片。

## 4. 状态与持久化

- `Idle → 校验 → 写入 Running → 保存 → 启动 worker → 增量事件 → 唯一 End → 保存终态 → Idle`。
- 翻译创建新 attempt，保留 `source_attempt_id`；编辑使用 expected text CAS；删除、分支、复制和 selected attempt 更新必须在事务提交后刷新内存状态。
- 搜索、工具、推理、usage、附件和生成图片都走同一事件归约；来源不拼入正文，媒体历史只保存引用和元数据。
- 接受前或终态保存失败不发起/不继续后续请求；旧数据原字节可读，内存状态可恢复，允许重试保存。
- SQLite schema 显式迁移；旧 v1 只作为导入源，未知版本拒绝，迁移失败不静默重置。
- 有界队列、每帧事件上限、取消和关闭仲裁保留；worker 不得因发送队列阻塞而无法退出。
- 数据目录单写者锁；媒体临时文件先同步，数据库提交引用后可见；无引用媒体可在清理阶段删除。
- schema v1 兼容只适用于导入，不限制新 schema 的候选、来源、翻译或媒体字段。
- 模型与搜索中的 SavedKey 字段及密文仍不变；密钥不进入历史、事件、UI DTO、日志或媒体引用。

## 5. 集成与兼容

egui/eframe现统一0.37.0（初次实现为0.33.3，升级前已本地提交基线）；依赖锁入Cargo.lock。框架不依赖产品，不增加插件系统/大trait。SavedKey用原有系统加密，禁止把产品邀请链接变成框架默认值。

AiHost::connection移除危险默认实现，逐个迁移实际实现。现有其它模块不借此重做；公开API变更先查引用。portable路径由current_exe解析data，不可写明确失败；LUMADESK_DATA_DIR仍显式优先。发布仍使用build-app.bat → dist/LumaDesk/LumaDesk.exe及installer ZIP，不搬动旧data。

## 6. 交付与验收

1. 核心：v1 导入、schema 迁移、候选树、编辑 CAS、删除、分支、选择、保存失败、取消、超时、重启和独占锁。
2. 文本：三协议流式/非流式、多轮、重试源模型、Markdown、复制和布局不重叠。
3. 事件：搜索来源、工具调用/审批、推理、usage/价格和唯一终态；正文与来源/状态分离。
4. 翻译：新请求、新 attempt、源回复不变、普通上下文不误用、失败可恢复、重启关系不丢。
5. 图片：附件校验/恢复/引用、生成或编辑真实消费者、有界响应、魔数/MIME、取消、损坏响应、重启媒体恢复。
6. 复用：LumaDesk 与独立宿主共用 ChatSession/ChatPanel；核心无 egui 反向依赖；不复制业务实现。

没有真实请求消费者、事件链和持久化字段的能力不宣称完成，也不绘制入口。

## 7. 实施结果与差异

- 文本 ChatSession、模型目录、三协议客户端、基础图片校验、搜索适配器和 usage 快照是现有基线；它们继续复用并扩展，不限制目标产品范围。
- 候选树、搜索事件持久化、翻译、工具/推理事件、附件历史、图片生成/编辑消费者及对应 UI 尚未完成，按上位设计的 P1–P4 实施。
- 现有文本实窗与回环证据只证明文本基线；不能替代搜索、翻译、工具或图片能力的真实请求、失败和重启验收。
