# AI 对话移植详细设计

日期：2026-10-23。状态：文本聊天核心、共享组件和产品接入已实施。上位方案：[01](01-AI对话移植与LumaKit复用设计.md)。本次落实 P0–P3；P4 的模型/搜索设置全面组件化仍是独立后续任务。

## 1. 文件与模块

- `LumaKit/crates/lumakit-ai/src/chat.rs`：由产品现有聊天提取 History/Conversation/Turn/Attempt、文件仓库和 ChatSession；不依赖 egui。
- `LumaKit/crates/lumakit-ui/src/chat.rs`：ModelOption、ChatAction。只包含本次已实现的动作，不建工具/图片占位接口。
- `LumaKit/crates/lumakit-egui/`：ChatPanel，原生渲染、模型搜索、历史弹窗、Markdown 缓存、输入与滚动状态；仅依赖 egui，不要求宿主使用 eframe。
- `LumaKit/crates/lumakit-support/`：提取 SavedKey/new_id；共享安全写入、单写者持有与严格便携路径。
- `LumaDesk/src/chat.rs`：只保留组合层：渲染组件、接收动作、解析保存模型并调用 session。
- `LumaDesk/src/model_settings.rs`：独立保存模型目录快照，无密钥 ModelOption 缓存；按完整身份解析连接，不每帧重建标签。
- `LumaDesk/src/main.rs`：实际唤醒、主题字体、关闭仲裁；移除未参与执行的空 UiSession/Backend。
- 共享组件增加一个独立可运行验收宿主，真实回环请求，不引用 LumaDesk 源文件。

## 2. 核心 API 合同

以下为本次实现签名。所有 ID 与 Protocol/ModelRef 的序列化保持旧格式。

```rust
pub struct ChatSession { /* 仓库、状态、任务；无 egui */ }
impl ChatSession {
    pub fn open(path: &Path, wake: Arc<dyn Fn() + Send + Sync>) -> Result<Self, String>;
    pub fn history(&self) -> &History;
    pub fn selected(&self) -> Option<&Conversation>;
    pub fn busy(&self) -> bool;
    pub fn save_failed(&self) -> bool;
    pub fn notice(&self) -> &str;
    pub fn poll(&mut self);
    pub fn cancel(&mut self);
    pub fn can_close(&mut self) -> bool;
    pub fn new_conversation(&mut self);
    pub fn select_conversation(&mut self, id: &str);
    pub fn delete_conversation(&mut self, id: &str);
    pub fn select_model(&mut self, model: ModelRef);
    pub fn set_draft(&mut self, text: String);
    pub fn retry_save(&mut self);
    pub fn send(&mut self, connection: AiConnection);
    pub fn retry(&mut self, connection: AiConnection);
    pub fn request_model(&self, retry: bool) -> Result<ModelRef, String>;
    pub fn report(&mut self, message: String);
}
```

`History { conversations, selected, model }`、`Conversation { id,title,draft,turns }`、`Turn {id,input,attempts}`、`Attempt {id,model,text,status,error}` 字段公开只读访问，session 持有唯一可变所有权。ModelRef/Protocol 沿用现有定义。所有对外变更方法自行检查 busy/save_failed，不能只依赖控件禁用。

发送由宿主先调用 request_model(false)，经真实来源 resolve 得到连接，再调用 send。普通 retry 使用最后尝试的源模型，显式 RetryWith 先选择目标模型并通过独立覆写路径调用；不把用户当前下拉当成默认重试源。不得把 endpoint ID 当 URL。连接内容必须与 request_model 匹配，API 内再次检查。

## 3. UI 合同

`ModelOption { model: ModelRef, name: String, provider: String, endpoint: String }`。不携带密钥、完整连接或文件路径。

`ChatAction`：New、Select(String)、Delete(String)、SelectModel(ModelRef)、Draft(String)、Send、Retry、RetryWith(ModelRef)、Stop、Save、OpenSettings。

`ChatPanel::new(instance_id)`；`show(&mut self, ui, session: &ChatSession, options: &[ModelOption]) -> Vec<ChatAction>`。返回动作由宿主绘制后执行。输入 UI 本地缓存，与 conversation ID 同步；每次编辑才发 Draft，避免每帧复制全文。实例 ID 隔离弹窗、滚动、模型搜索与编辑状态。

头部固定、composer 底部先占位、transcript 只用剩余区域。实现必须保存本帧 header/transcript/composer 实际 Rect 供布局测试，不能用测试中手写坐标替代。输入默认约80pt、展开约可用高度40%，错误独立滚动且不能推走按钮。控件28–30pt、正文13pt/行高约1.6、轮次16pt、块内12pt；源码是行为参考，非复制 CSS。

用户消息右对齐主题气泡；助手来源弱化、正文块、动作底置；旧尝试折叠。重试仅末次问题，显式换模型重答；无业务能力不绘制入口。历史弹窗提供搜索/切换/删除确认。正文用成熟兼容的原生 Markdown，保留原始源文本复制；外链仅HTTP(S)，不自动加载远程图片、不执行HTML。缓存按attempt ID和文本版本更新，限制过期缓存。

## 4. 状态与持久化

- Idle → 校验模型与上下文 → 添加 Running记录 → 保存成功 → 启动worker → Delta → 唯一End → 保存终态 → Idle。
- 接受前保存失败：撤销本次turn/attempt和标题变更，保留草稿，不发HTTP，进入保存失败恢复状态。
- 终态保存失败：内存保留完整状态，阻止后续修改/请求，允许重试保存；不能因保存失败覆盖原可读文件。
- 当前v1上下文仅取每个问题末次attempt且Completed，保持不变；失败、取消不回灌。1MiB边界保留。
- 有界队列、每帧最多128个事件；wake回调触发宿主重绘。Drop取消并排空队列再join，正常关闭先经can_close。
- 仓库持有单写者锁；第二个写实例明确报错，不默默覆盖。锁随持有句柄释放，不能仅靠残留文件存在判断。
- 写入唯一临时文件，sync_all后替换旧文件；替换失败原字节不动，清理自有临时文件。已有HistoryStore去除Windows先删文件的路径。
- v1线格式不变；未知版本拒绝；中断恢复为Failed，保留已保存内容。模型/搜索中的SavedKey字段及密文不变。

## 5. 集成与兼容

egui/eframe统一0.33.3；新渲染依赖先检查兼容性与许可，再锁入Cargo.lock。框架不依赖产品，不增加插件系统/大trait。SavedKey用原有系统加密，禁止把产品邀请链接变成框架默认值。

AiHost::connection移除危险默认实现，逐个迁移实际实现。现有其它模块不借此重做；公开API变更先查引用。portable路径由current_exe解析data，不可写明确失败；LUMADESK_DATA_DIR仍显式优先。发布仍使用build-app.bat → dist/LumaDesk/LumaDesk.exe及installer ZIP，不搬动旧data。

## 6. 验收与交付

1. 核心：旧v1回读、保存失败不重复问题、重试源模型、取消、缺终止帧、多轮上下文、关闭/重启、独占锁释放。
2. 布局：860×560、1200×800及高DPI，长中文/代码/表格/草稿/错误；实际矩形不重叠，发送按钮始终可达。
3. 实窗：观察消息与输入分区，发送、流式、停止、重试、历史；浅深色截图。无法观察时明确报告，不能用单测冒充。
4. 复用：独立egui宿主同组件真实HTTP；CLI核心无egui依赖；两个组件实例不串ID。
5. 发布：全套相关测试、正式打包与产物校验；重复打包data字节保持。设计01更新实施状态，README记录真实模块与命令。

不纳入：回答树、分支/翻译、图片、工具/联网、用量与价格、全部设置组件提取。它们不影响本轮文本对话完整交付，不绘制占位按钮。

## 7. 实施结果与差异

- 共享 ChatSession 保留原 v1 结构，实际文件仓库作为其具体内部实现，不另建没有第二实现的 Repository trait。产品 chat.rs 只转发动作与解析连接。
- `lumakit-egui` 使用 egui_commonmark 0.22.0（MIT OR Apache-2.0，关闭默认图片特性）与其同系 pulldown-cmark 事件范围做图片禁载/链接约束；egui 固定 0.33.3。未复制参考组件源码。
- 助手正文为 13pt，渲染库不提供整份 Markdown 的精确 1.6 行高配置，采用原生文本行距与段落间隔；不宣称像素级复刻。用户气泡单独使用 20.8pt 行高。
- 文件保存失败回滚、源模型重试、上下文、输出上限、终态、锁释放、布局/IME/Markdown/缓存均有行为检查。布局检查包含短窗口和2倍DPI；未宣称每种Windows实际DPI都做过人工视觉验收。
- 实窗已观察浅深色、历史弹窗、旧v1恢复、真实HTTP流式Markdown、停止、401、重试保留尝试，以及独立消费宿主的首条消息和真实回复。外部付费模型、真实系统输入法全组合和所有DPI人工截图未验。
- 流式跟随实测修正为末尾锚点请求，向上滚动后停止跟随；避免无限偏移造成首帧空白。正常关闭数据已保存，独立验收数据不进入发布包。
