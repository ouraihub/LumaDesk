# LumaDesk 日志与异常规范

适用：LumaDesk 生产代码及其调用的 LumaKit 共享能力。本文细化 `AI工程规范.md` §4、§5；日志格式和生命周期复用 `lumakit-observability`，不另建日志框架。界面诊断保持默认折叠，不改变聊天与设置布局。

## 1. 责任与级别

| 级别 | 场景 |
| --- | --- |
| INFO | 用户操作、独立后台任务、应用启动与退出的入口及成功/正常取消 |
| DEBUG | 服务、存储、外部调用成功边界；过期结果丢弃、非关键诊断 |
| WARN | 子操作失败、超时、降级、异常清理、未完成操作 |
| ERROR | 顶层最终失败、启动不能继续、持久化失败、数据不变量破坏、Rust panic |

root ENTRY/EXIT/CANCEL 为 INFO、ERROR 为 ERROR；child ENTRY/EXIT/CANCEL 为 DEBUG、ERROR 为 WARN；TIMEOUT/UNFINISHED 为 WARN。一次异常只有一个最终 ERROR 所有者，允许 child WARN + root ERROR，禁止 service/UI/notice 各记 ERROR。失败展示不再次报警；日志查看轮询不产生日志。

## 2. 操作与调用链

- 用户动作、独立后台任务建立 `TraceContext::root`；同一动作下层用 `operation(&trace, ...)`，不在每个纯函数建立 span。
- 必须覆盖：启动配置加载；模型/线路/密钥保存与启停；目录刷新、检测、同步及应用；搜索配置/凭据保存、搜索/读取/检测；MCP 配置；外观保存；聊天持久化、附件操作和发送准备失败。
- 每个操作恰有一个终态：finish、fail、cancel 或 timeout。UNFINISHED 仅表示意外中断，不能用于正常控制流。
- 线程/executor/channel 边界传递上下文；worker 与 completion 在同一操作上下文执行。异步 future 用 instrumentation，不跨 await 持有 entered guard。
- 用户取消可以丢弃尚未应用的成功结果，但不得覆盖已经返回的真实失败或 worker panic。页面关闭、身份/代次变化丢弃结果须 DEBUG 说明固定原因，不能冒充用户取消或已应用成功。
- 不在 Entity::update 中再次读写同一实体；不要用 catch_unwind 掩盖重入。禁止把 panic 转成普通网络失败并继续批量应用部分状态。

## 3. 字段与隐私

事件名采用稳定点分名。记录内部 ID、错误码、HTTP status、数量、字节数、耗时；调用链由 formatter 输出 TraceId/SpanId/ParentSpanId/ME/Layer/SourceFile/SourceLine/EV/RT。SourceFile 仅保留仓库相对源码定位，不输出开发机绝对目录。

所有级别禁止输出：密钥、token、Authorization/Cookie、用户输入/回答、工具参数/结果、原始 HTTP body、SQL/绑定值、完整 stderr、用户绝对路径、外部 URL 路径/query 和不可信响应头原文。request-id 等外部标识只能记录安全关联哈希，不把长度限制或替换当前 API key 当作完整脱敏。

`%error`、`?error`、`format!("{error:#}")` 必须逐项证明安全。默认只记录 typed code、OS kind/code 或固定分类。DEBUG 不享有安全例外。循环失败汇总，不逐模型/文件/token 输出日志。

## 4. 错误与持久化

- 预期错误以类型/稳定码分类，不能按错误文案分支。网络分类使用 reqwest 类型属性及 HTTP status。
- 存储边界不将 SQL/I/O/JSON 外部原文送入 UI；使用简明中文、稳定码和真实 TraceId。输入校验错误不得归类为数据库写入失败。
- 捕获错误只能按明确分类恢复、补上下文传播、或在最终边界记录并通知。不得正常业务 `let _ = result`、`.ok()` 静默吞错。
- 写入成功后才更新已保存状态；失败保留草稿/回滚，禁止自动重放副作用未知的写操作。聊天生成成功不等于聊天记录保存成功，后者须独立失败事实且避免逐 token 重复报警。
- join/channel 失败须区分正常关闭与线程异常；资源清理尽力而为也应记录 DEBUG/WARN 固定摘要，不宣称未成功的清理已完成。

## 5. Panic 与启动

共享 LogHandle 初始化后安装进程级 Rust panic hook：同步向同一文件写 ERROR、稳定 RUST_PANIC 码、源码位置、线程、载荷分类/哈希和调用栈；继承当前操作上下文。panic 不受普通日志过滤器关闭影响，不调用原样打印 payload 的默认 hook，不改变 unwind/abort 语义。不得在正式用户进程制造崩溃。

日志初始化之前的故障不能伪称已落盘；初始化之后启动失败必须有明确 ERROR 与诊断 ID。启动成功只能在必要配置加载完成后记录。

边界：磁盘不可写不能保证落盘；Rust hook 不覆盖系统强杀、断电、访问违规、栈溢出或直接 allocator abort。无符号时调用栈可能只有地址，不宣称已符号化。普通日志不包含用户数据库或内存转储。

## 6. 开发与验收

修改前读本文、AI工程规范和目标调用链；明确入口→service→repository/external→completion 的资源与最终错误所有者，检查全部调用方。

回归覆盖成功、输入拒绝、上游失败、持久化失败、取消、超时、关闭/stale 与 panic。读取真实 writer 输出核对 INFO 可见入口/终态、DEBUG 层级、父子链与唯一最终 ERROR，扫描合成秘密/正文/路径/响应头标记。用临时数据、本地回环和隔离子进程，不访问真实密钥或供应商。

运行受影响测试、fmt、严格 clippy 与编译；GUI 错误展示须实际启动观察。不得用源码字符串存在或编译成功代替行为证明。验证命令、实际结果、未覆盖范围记录在 BUILD.md；未观察项不写“全部通过”。
