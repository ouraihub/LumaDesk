# LumaDesk

独立的纯 Rust 桌面宿主 App（AI agent 工作台）。本分支 `experiment/gpui-kit` 用 GPUI（gpui-kit 0.9.0）绘制原生窗口，接入 `LumaKit` 的 `lumakit-design`、`lumakit-gpui` 与 `lumakit-ai`；`main` 分支仍是 egui 版。

## 运行

```bat
scripts\build-app.bat
scripts\run.bat
```

Rust 相关检查统一通过 `scripts\cargo-msvc.bat`，它会优先复用 `PORTABLE_MSVC_ROOT`，默认使用 `D:\Applications\msvc-portable\msvc`，避免 Git 自带 `link.exe` 抢占 MSVC linker。

正式打包先运行框架与宿主检查，再构建 Windows x64 发布程序。产物分工：

- `dist/LumaDesk-GPUI/LumaDesk-GPUI.exe`：GPUI 日常直接运行，`run.bat` 只启动这里，不临时编译。
- `dist/LumaDesk-GPUI/data-gpui/`：运行时数据，重新打包只替换发布文件，不复制或删除数据目录。
- `dist/gpui/installer/<版本>-<构建标识>/LumaDesk-GPUI_<版本>_x64-portable.zip`：便携分发包，包含 EXE 与依赖/模型目录许可，不含密钥、聊天记录或缓存。
- `dist/gpui/release.json`：本次发布版本、精确包路径及 SHA-256；执行 `powershell -NoProfile -File scripts/release-artifacts.ps1 -Verify` 可复核 EXE、ZIP 及包内 EXE 的一致性。

`scripts/build.bat` 仅供快速编译，输出仍在 Cargo `target`；正式查看或分发使用 `build-app.bat` 的 `dist` 产物。旧 `target/release/data` 不自动搬迁，避免覆盖现有资料；迁移时先关闭程序，再自行搬移完整 `data` 目录。也可保留 `LUMADESK_DATA_DIR` 显式指定数据路径。
发布校验直接使用 .NET SHA-256 流式计算；测试、发布和哈希验证三阶段全部成功后，才以 `dist/LumaDesk-GPUI/LumaDesk-GPUI.exe` 为本次可运行产物。运行旧的 target 或未更新 dist 不能用于验收新版界面。

启动台提供对话、工作、笔记、知识库、翻译入口；对话与「设置 → 模型服务 / 网络搜索 / MCP 工具 / 用量统计 / 外观」可用，其它应用业务未接入。外观页来自 `lumakit_design::appearance`：主题、跟随系统、强调色与密度，保存到 `settings.db`，重启及重新打包后保留。

LumaKit 仍是独立框架工程；本项目通过路径依赖使用它，不属于 LumaKit 的 `examples`。

界面颜色、尺寸和字体只来自 `lumakit-design` 的主题角色与令牌，详见 [构建说明](docs/BUILD.md)。后台会话在定时轮询中归约，窗口最小化时仍能完成保存。

## 设计与实现规划

[聊天总设计](docs/01-AI对话移植与LumaKit复用设计.md)、[聊天详细设计](docs/02-AI对话移植详细设计.md)和[聊天任务追踪](docs/06-聊天功能任务追踪.md)以新项目目标为准：当前文本链路是基线，候选树、翻译、搜索来源、工具/推理、图片附件和生成图片按同一真实请求—事件—持久化链路继续实现。现有代码缺口不是永久产品限制。

所有界面修改先读 [项目长期约束](AGENTS.md)：以已运行参考的结构与交互为准，禁止擅自发挥，诊断默认折叠，交付须有实窗对照。

[模型设置界面与交互改造](docs/03-模型设置界面与交互改造.md)：布局、管理弹层、独立启用提交、统一设计 Token、外观偏好、任务清单及真实验收记录。

仓库内的 [egui 组件使用 skill](.claude/skills/egui-components/SKILL.md) 面向任意 egui UI 项目，提供组件选型与按任务读取的表单、布局弹层、主题反馈规则及正反例；可整体复制，不依赖本项目目录或框架。可运行样本按需使用。

密钥行点击眼睛展开复制、修改、删除与隐藏操作，删除需要确认；右侧钥匙管理多密钥。API 地址输入框内的复制按钮复制当前显示地址，编辑与失焦保存行为不变。

## 对话

在模型服务中填写线路、密钥和模型并启用服务商，再从启动台打开对话，选择模型并新建会话。Enter 换行，Ctrl+Enter 或发送按钮提交；文本流式回复、停止、重试、复制及会话切换/删除已是可运行基线。

输入区底栏提供新对话、网络搜索、添加工具、模型与推理组合选择及发送/停止。`＋ → 快捷面板` 打开「自定义工具栏」，控制真实工具是否固定、排序和恢复默认；偏好跨对话共用并重启保留，不执行工具或改变当前请求开关。现有“用量”入口展示提示词上下文估算、当前对话累计以及默认折叠的上一回答详情；费用按币种累计，明确标记配置/目录参考估算，未返回用量或没有价格时标未知。

聊天会话、草稿、尝试状态、用量和计费快照保存在同一数据目录的 `chat.db`，旧 `chat-history.json` 仅作显式迁移源。保存失败保留可恢复状态并阻止继续请求；请求总时限、上下文预算和媒体限制由连接/运行合同统一校验。

「设置 → AI → 用量统计」读取独立请求账本，支持全部/近7天/近30天及按模型/服务商/UTC日期分组。复制和分支保留请求 ID，不重复记录消耗；删除聊天不抹去已记录统计。旧记录缺少时间或请求身份时标注覆盖限制，不补造日期，无法可靠去重过去已经产生的历史副本。

模型 ID 精确匹配内置 OMP 目录时，未手填的上下文和可支持元数据可自动补全，手工设置优先；模型窗口是公开参考上限，不保证中转线路不另设限制。目录参考价仅估算 token 费用，不代表中转实际扣费。目录更新不重算既有请求价格快照。

每个问题最多 4 个附件；文本合计不超过 1 MiB，单图不超过 4 MiB，不静默截断。附件内容随问题保存，重试及重启不依赖原文件；图片字节存于 `chat-media`，数据库仅保存媒体引用。文件选择在后台等待，聊天主界面不会因系统对话框卡住。

联网开关使用 Responses / Anthropic 原生搜索；Chat Completions 明确拒绝，不自动借用网络搜索设置中的服务商。推理下拉只列出所选模型已声明的强度，默认沿用模型配置。生成图片是聊天工具开关：保留聊天模型和上下文，由聊天模型调用 `generate_image`，独立图片模型执行 OpenAI 兼容 `images/generations` 后回填工具结果，再继续文字回复；不是把用户原句直接转发给图片接口。绘图提示校验为 1–4000 个 Unicode 字符，尺寸支持 1024x1024、1024x1536、1536x1024；每次回复最多执行两次，失败计入，重复调用 ID 不重复执行，HTTP 不自动重试。工具错误保留状态及请求 ID，取消终止整轮；后续文字失败仍保留已落盘图片。重试沿用原问题的绘图配置，当前不处理参考图编辑。不发送 `response_format`，不以通用字段合法代替真实供应商验收。

聊天头部、消息滚动区和底部输入区独立分配；历史在弹窗中切换，支持展开输入与回到底部。回复按短来源、工具状态、内联图片、正文和操作分层；用量及原始诊断默认折叠，保存/插入/导出等次要动作进入更多菜单。图片预览仅加载会话已登记的本地媒体，不为 Markdown 开放文件或网络图片加载器。通用界面来自 `lumakit-gpui::ChatPanel`，产品只提供已保存模型选项和连接解析。数据目录使用内核文件锁，同一目录不能同时开启多个写入实例；目录不可写时明确报错，不静默新建其它位置的数据。

对话协议检查：在 LumaKit 工程执行 `cargo test -p lumakit-ai --release`；宿主行为检查使用下方 `scripts\check.bat`。

## 设置与验证

- 右上角或左下角进入设置；浅色/深色按钮切换当前窗口主题。
- 模型服务支持多服务商、多线路、加密多密钥、三种协议、真实模型检测、选择同步和手动模型能力设置。检测只统计，不会替换模型；同步保留手动模型和已有能力。
- 内置七牛云、硅基流动、Fenno 三个服务商及获取密钥链接，默认关闭、不带密钥或模型。首次使用或旧配置升级时补入一次；同名服务商保留原配置，已初始化后删除不会在重启时重新添加。
- 网络搜索支持 Tavily、Brave、Exa；网页读取支持直接获取和 Jina Reader。只有显式点击才联网；检测先保存有效草稿。黑名单、结果数和 Unicode 截断在高级设置中配置。
- 密钥使用 Windows 当前用户系统加密；显示/复制为显式操作，离开设置清除已显示明文并取消请求。系统剪贴板由用户管理。401/403/429 才有限轮换同服务商密钥，不跨服务商重试。
配置保存在 `lumakit_support::data_root("luma-desk")`，也可用 `LUMADESK_DATA_DIR` 指定数据路径。模型目录使用 `providers.db`，网络搜索和外观使用 `settings.db`，聊天使用 `chat.db`；旧 JSON 仅作一次性导入源并保留。损坏或不支持版本会显示错误，不静默重置。
- 模型请求已具备输出上限、推理方言、原生搜索门控、流式/JSON 模式、上下文预算、工具能力三态和计费快照；候选、来源、工具、翻译与媒体能力按聊天详细设计扩展，未完成前不显示假入口。

模型编辑页按 Cherry `ModelDrawer` 的信息层级改为紧凑单列：ID 旁复制、名称/分组、用途下拉、更多设置下的分类/能力与输入模态、Token 限制、流式开关和价格卡片。模型类型、推理/工具能力及视觉/音频/视频输入声明可点击选择，保存后生效，取消不落盘。能力声明不是本次请求参数；音频/视频声明会保存并显示图标，但当前宿主未接入对应上传链路。最大输入 Token 有独立发送前预算校验；清空覆盖恢复自动。标题和保存/取消固定、表单独立滚动。

推理能力参与协议兼容的精确目录补全：支持的 OpenAI effort 和 Anthropic adaptive 模式继承来源档位，未知/不兼容模式不伪造能力。模型编辑页不配置档位、默认强度、协议方言或推理预算；具体强度只在聊天组合选择器使用时调整。“默认”不发显式强度参数，选择具体档位才进入真实请求字段，不擅自取第一档 low。

模型列表与聊天选择器使用同一份有效能力配置显示视觉、推理、工具及原生联网图标，筛选也使用相同结果；不只读取手工勾选值。精确目录可补全视觉/工具声明，显式停用优先，未知模型不显示猜测图标。图标使用主题角色与内置资源，不复制上游品牌资源。
网络搜索请求在宿主处理结构化 HTTP 状态，复用 LumaKit 请求合同和结果处理；没有通过错误字符串推测是否换钥。

诊断日志位于数据目录 `logs/app.log`，默认 Info，5 MiB 后轮转并保留 `app.log.1`。聊天请求关联 conversation/turn/attempt ID、模型与协议；图片请求记录接口、提示词字节数、尺寸和状态，不记录提示词正文。上游 HTTP 错误统一记录状态、白名单请求 ID 和最多 8 KiB 脱敏正文；超限正文整段丢弃。Authorization、Cookie、完整请求头和图片 Base64 不写日志。`AiError::Http` 保留状态码、请求 ID、正文，UI 仅在展示边界转换为文字；不能通过错误字符串判断状态或自动重试计费请求。

运行 `scripts\check.bat` 执行框架和宿主行为检查；正式打包使用 `scripts\build-app.bat`，快速编译使用 `scripts\build.bat`。均复用便携 MSVC 环境，可由 `PORTABLE_MSVC_ROOT` 指定。
